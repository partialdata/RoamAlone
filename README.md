# RoamAlone

A single-player van-life horror prototype built with Unreal Engine 5.8 and C++/Blueprints.

## Local setup

Install Unreal Engine 5.8 (currently developed with 5.8.4), its C++ build toolchain,
and Git LFS before cloning. Rider is the project's C++ editor.

```powershell
git lfs install
git clone https://github.com/partialdata/RoamAlone.git
cd RoamAlone
git lfs pull
```

Open `RoamAlone.uproject` in Unreal or Rider and build the editor target as needed.
Install RiderLink through Rider when prompted; its local plugin copy is ignored.
Read `AGENTS.md` before making gameplay changes.

## Version control

Commit `.gitignore` and `.gitattributes` together with project source, config,
required content (including external actor/object packages), and `.uproject`.
Unreal maps/assets and common binary art/audio/video formats use Git LFS.
Generated builds, caches, local IDE files, and `Saved` backups are ignored.
Keep required project-owned plugins and platform resources in version control.

Before committing or pushing assets, review `git status`, `git lfs status`, and
`git lfs ls-files`. A normal `git push` uses the LFS pre-push hook to upload the
corresponding LFS objects. Each new clone needs Git LFS installed locally.

## Van camera prototype

The startup map is `/Game/VanPrototype/Maps/Lvl_VanPrototype`. Play as Quinn,
approach the yellow door, aim the centre crosshair at its panel or handle,
and press **E**
(gamepad **X / left face button**) to slide it open. The panel's destination
must be clear; normal close-range interaction is allowed.
Walk through the doorway to switch to eye-level first person. Walk outside
to restore the template's third-person camera through a short position/FOV
blend. Tune **Exit Camera Blend Duration** on `BP_ThirdPersonCharacter`
(default 0.45 seconds; zero restores an instant switch). Look and movement
stay live; stepping back inside reverses an unfinished blend. Intermediate
camera positions use the spring arm's collision probe, and the local body
remains headless until the view clears the character. The door can be closed and
reopened from inside; its position alone does not change the view.

Use the wall-mounted switch beside the door to operate it from inside.
The handle is attached to the sliding door and moves with it.

The original Third Person map is preserved. The same possessed Character and
Enhanced Input movement/look bindings work in both camera modes. Inside,
walking is slower. Jumping is disabled everywhere through Character Movement's
**Can Jump** capability, and Space / gamepad jump mappings are removed from
`IMC_Default`. Normal walking, gravity, and the 45 cm step-up height remain enabled.
Window panes block the capsule and
third-person spring arm; the local body hides the neck/head while the full
world mesh supplies shadows and reflections. Door movement is instantaneous.

Inside, aim at the red **LOCK** tab on the side of the inside door-control plate and press
**E / gamepad X** to lock or unlock. The separate door switch still opens/closes
the door. Closing does not lock automatically. Locking an open door is refused;
a locked door refuses opening from either side. Prompts show the current lock
state and brief feedback explains a refusal. Unlock from inside, then open the
door normally to leave. No keys or inventory are required.

The player Blueprint uses a deliberate walking pace: **180 cm/s outside**
(`Character Movement → Max Walk Speed`) and **120 cm/s inside**
(`Interior Walk Speed`). Tune these in `BP_ThirdPersonCharacter`; the van
transition caches and restores the configured outside speed.

Edit the van's walls, windows, panel, handle, and switch directly in the
Components viewport of `/Game/VanPrototype/Blueprints/BP_GreyboxVan`.
The Blueprint asset owns its model and materials. Its native parent owns
door validation, movement of the assigned door assembly, and the interior
trigger. No van meshes are generated by C++ at runtime.

Run `RoamAlone.Van` in Unreal's Session Frontend Automation tab for focused
door, handle attachment, collision, and camera-transition tests. For input/demo-map setup,
build `RoamAloneEditor`, then run the installed `UnrealEditor-Cmd.exe` with
the project path, `-run=pythonscript`,
`-script="D:/unrealProjects/RoamAlone/Tools/Editor/setup_van_prototype.py"`,
and `-EnablePlugins=PythonScriptPlugin,EditorScriptingUtilities`.
The setup script requires the authored van Blueprint, creates a missing test map,
and preserves an existing one. It does not regenerate the model.

The Sprinter reference blockout uses a 593.2 × 202 × 282.6 cm exterior envelope
and a 336.6 × 178.7 × 200.9 cm cargo space. Furniture sizes are prototype choices:
a 135 cm deep raised rear bed with storage, a 50 cm deep galley with sink,
faucet and cooktop, a 35 cm deep bench, overhead cabinets, and a blocked-in cab.
The standing aisle is 93.7 cm wide; Quinn's capsule remains 84 cm wide and
192 cm tall. The floor is 65 cm above ground, reached by a 32.5 cm step.
The 120 cm side door slides rearward. Furniture is solid greybox collision;
bed use, seating, and appliance interactions are not implemented.
All furniture and shell pieces are editable Blueprint components. The cab is
outside the walkable cargo area for this layout test.

## Firewood task

`Lvl_VanPrototype` starts with **Collect firewood: 0/3**. Find three scattered logs,
aim at each within reach and press **E / gamepad X**. Carrying is represented by
the persistent objective text for this slice; there is no inventory screen or
new carry animation. At the labeled stone fire pit, aim at its center or rim
and interact again after collecting all three. Each collected log disappears;
the complete stack appears in the pit on delivery. An early return explains
the missing logs and preserves progress. Lighting the fire and cooking are
not implemented.

`AFirewoodTask` owns the three states (`Available`, `Carrying`, `Placed`) and
implements the existing interaction interface. It rejects placement without
all three logs, repeated pickups, and placement by another pawn. `ResetTask`
restores every log, the empty pit and objective; losing the carrier also resets
the task. A clean PIE run starts fresh. `OnTaskStateChanged` updates the HUD
without polling after every pickup and on placement. The placed night director
observes this same event to start the retreat objective after delivery.

The authored asset is `/Game/VanPrototype/Blueprints/BP_FirewoodTask`. Its
`PickupLog1`, `PickupLog2`, and `PickupLog3` are independently collectible meshes
listed in the Blueprint's `PickupReferences`. Their fixed locations form a short
route around the clearing; move those meshes to tune the route. `FirePitAssembly`
positions the pit independently;
`PlacedWoodAssembly` is a child of the pit and contains the completed wood stack.
The pit and placed-wood component references are assigned in the Blueprint defaults.
Pickup meshes use query collision while available; the placed stack has no
collision. Keep one task actor in this persistent prototype map: the player
resolves it once at initialization.

## First encounter

The placed `/Game/VanPrototype/Blueprints/BP_NightDirector` connects the greybox
loop. Deliver the wood, hear a nearby snap, and return inside. Night begins with
eight seconds to prepare before footsteps, knocking, and a handle attempt. The
director reads the van's current state at the attempt: locked holds, unlocked
opens through `TrySetDoorOpen`, already open stays open, and blocked movement is
refused. Closing and locking remain the player's choice; no state is forced.

After the attempt, use **E / gamepad X** on the orange **HORN** control below the
inside door switch. The horn plays once, followed by retreating footsteps, a
quiet interval, and a fade to morning. At morning the same control offers
**Restart prototype**, which reloads the map. Captions and objectives explain
the sequence without requiring sound. Stepping outside before a critical cue
defers that cue until the player returns; early entry never skips the wood task.

`ANightDirector` owns the short phase sequence and cancellable timers. Its child
Blueprint assigns the five sounds and assembles the horn prop. Its
`RequestTimeOfDay` event calls `BP_CampsiteNightSky.ApplyPrototypeTime`; that
project-owned function disables automatic time advancement and sets UDS time.
The sequence uses 17:00 for collection, 23:00 for shelter, and 08:00 for morning.
Vendor content is unchanged. Audio anchors are relative to the van, and the
placed director is attached to it.

For development, `ResetEncounter` restores the task, timers, sound, time and a
closed, unlocked door; it refuses an obstructed close. `DebugStartShelter`
requires the player to be inside and starts the preparation phase after a safe
reset. Neither method bypasses door clearance or lock validation. Tune the
preparation and quiet delays in the placed director. No enemy AI, generic quest
framework, cooking or additional scares are included.

Source WAVs and their pending attribution records are under `SourceAssets/Audio`;
imported Sound Waves are under `/Game/VanPrototype/Audio`. Exact download pages,
authors and licenses still need recording before distributing these sounds.
Run `RoamAlone.Firewood` for state, reset, ownership, obstruction and interaction
route checks, or `RoamAlone.` for these plus the van regressions.

## Reusable interaction

`UInteractionComponent` on the player owns targeting, physical reach and
obstruction checks, focus, and brief action feedback. It polls locally at 10 Hz
without Tick and traces again for every action. The Character forwards the
existing Enhanced Input `IA_Interact` **Started** event, supplies its active
camera when the view changes, and connects presentation events to the prototype
HUD. Door state remains owned by the van. The interaction component has no van
or widget dependencies.

To author another interactable in Blueprint:

1. Add **Interactable** under **Class Settings → Implemented Interfaces** on
   the prop's Actor Blueprint. `BP_GreyboxVan` inherits it from its native parent.
2. Implement **Get Interaction Prompt**. Return action text such as “Turn on
   light”; return empty text when the hit component offers no action. This is a
   read-only query and must not change gameplay state.
3. Implement **Try Interact**. Check the prop's current state and the supplied
   hit component, perform the action once, and return success. Return false and
   optional **Feedback** text when refused. Keep gameplay rules here; the HUD
   must never change the prop's state.
4. Give the usable mesh collision that **blocks Visibility**, the default
   interaction trace channel. The hit's Actor must implement the interface.
   Check the hit component if only a handle, switch, or panel should respond.
5. Compile, place the prop, and test E/X nearby, out of reach, and behind a wall.

On another Pawn, add **Interaction Component**, call **Set View Source** with
its active camera (or allow the PlayerController view fallback), and forward
one Enhanced Input Started event to **Try Interact**. Bind
**On Presentation Changed** to a widget and read **Get Prompt / Get Feedback**
once on initialization. Use **Deactivate / Activate** to suspend/resume
interaction for a sequence or UI flow. The component clears focus and its timer
when deactivated or destroyed. It keeps weak references to targets and cameras.

Run `RoamAlone.Interaction` for stale-focus, obstruction, target destruction,
component activation, and surface-filtering checks, plus `RoamAlone.Van` for
door and camera regressions.

## UDS night presentation

The prototype map uses the project-owned `BP_CampsiteNightSky` child of
`/Game/UltraDynamicSky/Blueprints/Ultra_Dynamic_Sky`. Installed content reports
**9.7**; use the [vendor's 9.7 documentation](https://www.ultradynamicsky.com/Documentation/V9/9-7).
The child owns the preset, with no vendor asset edits or native UDS dependency.

**Fresh clones require a licensed local installation of Ultra Dynamic Sky 9.7.**
Add the purchased content to this project at `Content/UltraDynamicSky` before
opening the prototype map or its sky Blueprint. This public repository excludes
the vendor pack from version control; it tracks our child Blueprint and map.

The editor preview uses **2350 (23:30)**. During play the night director requests
**1700 (17:00)** for gathering, **2300 (23:00)** on retreat into the van, and
**800 (08:00)** at the ending through `ApplyPrototypeTime` on the sky child.
Time animation, random starting time, system
time, and randomized cloud formation are disabled for repeatable playtests.
Cloud Coverage is 5.5, Fog is 0.3, Night Brightness is 0.65, moon intensity is
0.4, and the moon light color is cool blue. UDS controls exposure with an
EV100 range of -4.5 to 0.5 and night exposure bias -0.25. Tune the child or the
placed actor in Unreal; keep UDS as the sky/light/time authority.

The previous standalone directional light, sky light, and sky atmosphere were
replaced by UDS' built-in environment components. The existing interior light
is movable, warm (2900 K), 25 lumens, with a 360 cm attenuation radius.
UDW content is installed, but no weather actor or precipitation is enabled in
this scene; indoor rain exclusion and weather audio remain untested.
